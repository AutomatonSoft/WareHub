# Frontend E2E Tagging Policy

## Цель
- Предсказуемо раскладывать тесты по suite (`smoke`, `flaky`, `visual`, `perf`) и ускорять triage.

## Теги

### `@flaky`
- Используй, если тест периодически падает из-за нестабильного окружения/таймингов, а не из-за продуктового бага.
- Такие тесты запускаются в отдельном Playwright project: `chromium-flaky` (повышенные retries/timeout).
- До добавления тега обязательно:
  - проверить, что тест стабилен локально в изоляции;
  - попытаться устранить нестабильность селекторов/ожиданий.

### `@visual`
- Используй для snapshot/visual regression сценариев.
- Тест должен:
  - быть детерминированным (фиксированные viewport/theme/locale/timezone),
  - не зависеть от случайных данных.
- Запуск в CI контролируется `E2E_VISUAL=1`.

### `@slow`
- Используй для тяжёлых сценариев (длинные setup/flow, много шагов, долгие интеграции).
- `@slow` тесты не должны попадать в быстрый smoke-путь без явной причины.
- Рекомендуется запускать `@slow` отдельно или в nightly/optional suite.

## Правила применения
- Один тест может иметь несколько тегов (например, `@visual @slow`).
- Тег добавляется в title `test`/`describe`:
  - `test("inventory export @slow", async () => { ... })`
  - `test.describe("visual checks @visual", () => { ... })`
- Не использовать теги как замену исправлениям. Если flaky устранён, тег `@flaky` нужно удалить.

## Связь с текущими скриптами
- `npm run test:e2e:flaky`: запускает только `@flaky`.
- `npm run test:e2e:visual`: запускает visual spec.
- `npm run test:e2e:smoke`: основной быстрый регрессионный проход.

## Чеклист перед PR
- Новый тест помечен корректным тегом (или осознанно без тега).
- Если добавлен `@flaky`, в PR описана причина и план стабилизации.
- Если добавлен `@visual`, проверены baseline и snapshot budget.
