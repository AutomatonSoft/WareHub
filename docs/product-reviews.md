# Проверки публикаций

## Локальная реализация

Вкладка `/reviews` показывает последние попытки `publish`/`update` из постоянной
очереди orchestrator отдельно для товара и назначения: JV/XL сайты, HOOD JV/XL,
Kaufland JV/XL, OTTO JV/XL, eBay JV/XL/DEP. Прямые legacy batch-задачи и операции
активации/деактивации в эту выборку не входят.

Поиск работает по KID и EAN. Страницы содержат до 50 последних назначений;
фильтр ошибок применяется внутри страницы. При пустой странице проверяйте
доступность кнопки следующей страницы. Данные обновляются каждые 15 секунд.

Редактор загружает сохранённый payload конкретного назначения. Изменения остаются
локальным черновиком до подтверждения отправки; закрытие страницы их не сохраняет.
EAN, SKU и productReference при повторе неизменяемы. Сервер восстанавливает KID,
назначение и автора, не доверяя присланным браузером значениям. Новая попытка
не удаляет исходную историю. Двойная отправка блокируется idempotency key и
проверкой последней попытки под SQLite write lock.

## Статусы и связь с Sofort list

- `queued`/`running`: внутренняя обработка, не подтверждение публикации.
- OTTO/Kaufland: используются те же записи мониторинга публикации, что и для
  Sofort list. HTTP 202 не считается публикацией. Отказ OTTO и ошибки Kaufland
  видны в редакторе; обычное ожидание модерации не разрешает повторную отправку.
- Для остальных каналов успешность определяется сохранённым результатом
  подтверждения EAN mapping, а не новым запросом публичной карточки.
- Новая попытка сохраняет mapping через существующий механизм сервиса; для
  OTTO/Kaufland зелёная отметка появляется после подтверждения монитором.
- При недоступном статусе или несовпадении OTTO task ID повтор блокируется.
- Старые ошибки с pool EAN без записанного фактически отправленного EAN
  блокируются: идентификаторы нельзя угадывать или выделять повторно.
- Для HOOD перед повтором проверяется существование товара: подтверждённый
  существующий товар обновляется, подтверждённое отсутствие разрешает создание;
  неоднозначный/cached результат блокирует отправку.

## Контракты

- `GET /api/v1/orchestrator/reviews?offset=0&limit=50&q=...`
- `GET /api/v1/orchestrator/reviews/{job_id}?target=hood,account=jv`
- `POST /api/v1/orchestrator/jobs` с `Idempotency-Key` и полем
  `review: {source_job_id, target, payload}`. Поддельный `command.review_origin`
  отклоняется. Ссылку на источник назначает только сервер после проверки.
- Внутренний `POST /api/v1/marketplace/publication-states/` принимает максимум
  100 записей `{key, marketplace, account, ean}` и требует сессию или доверенный
  сервисный токен. Чтение snapshots проходит через авторизованный frontend proxy.

## Выкатка и откат

Нужны согласованные версии frontend, orchestrator, database-service и gateway.
Новых таблиц, migrations и env-переменных нет. Перед reload gateway обязательна
проверка Nginx-конфигурации. Откат — возврат предыдущих образов и gateway config;
история задач остаётся в прежней SQLite, добавленные JSON-поля необязательны.

Эта документация не подтверждает выкладку или реальные повторные публикации:
локальные тесты используют изолированные базы и заглушки провайдеров.
